Shared Adam Memory Repair
Domain: Scientific machine learning / native neural checkpoint tensors and optimizer response observations. Scoring: higher is better. Compute: one A10G GPU, 90 minutes end to end. From-scratch challenge (no pretrained controller weights).

Objective
Infer enough about two private optimizer memories to choose one shared order of eight image minibatches. The same order must reduce the two learners' later prediction divergence while preserving each learner's classification capability. Your submitted object is an executable permutation, not an image class prediction or a reconstructed checkpoint.
Each request supplies a common weight vector, fixed diagnostic responses from the two branches, real photographed object crops and labels, and a fully specified small learner. The branches have different Adam moment buffers. Training requests additionally reveal those buffers and one feasible reference order. Evaluation requests omit the moment buffers and reference order; image class labels remain public. A reference is one successful construction, not a unique answer or a certified global optimum.
There are 1,680 training requests from 12 source capture sequences and 420 evaluation requests from four different sequences. Evaluation uses Tools objects; training uses Food and Kitchen objects. These are independently seeded optimizer experiments, but they reuse a curated subset of 192 photographed frames; they are not 2,100 independent camera captures.

Learner and controlled histories
Convert each RGB crop to float64 and divide by 255. Average its nonoverlapping 3 by 3 pixel blocks to an 8 by 8 RGB array, flatten in row-major order to 192 values, then apply (value-0.5)*2. The learner is a 192-input, 12-hidden-unit tanh network with a four-class softmax output. Its flattened parameter order is (192,12) input weights, (12,) hidden bias, (12,4) output weights, (4,) output bias. This is a small multilayer perceptron, not a pretrained visual backbone.
Each repair or diagnostic step computes the mean cross-entropy gradient on its specified four-image batch. The construction warm-up uses eight-image batches. Adam uses the public counter, ordinary first and second moments, bias correction, and no weight decay. Its exact float64 reference is embedded in learner.py.
Construction first performs 24 warm-up updates, then runs two different orders of the same 16 historical minibatches. The organizer explicitly restores both branches' weights to the common pre-history weight vector while retaining each branch's resulting moments and counter 40. This rollback is a controlled state intervention. The supplied states are not untouched endpoints of naturally converging histories. Historical batches and their orders are not participant input.
For each branch and each of the two diagnostic minibatches, a disposable copy of that starting state takes exactly one update. The supplied diagnostic probabilities are then read on monitor indices [0,1,3,6,9,10], in that order. The two probes are independent forks, not consecutive updates. They do not advance the repair starting state. Baseline probabilities can be calculated from the common public weights. No additional hidden-state queries are available.

Submission and execution
Submit a CSV with exactly id,prediction, containing each evaluation ID once. Encode prediction as a JSON list containing every integer from 0 through 7 exactly once, for example [0,1,2,3,4,5,6,7]. Boolean values, repeated indices, omitted indices, extra columns and malformed JSON are invalid.
The grader executes this same eight-step order from each branch's common weights and true private moments. Every indexed batch is consumed exactly once. You cannot reset moments, edit weights, change learning rates, insert or repeat batches, omit steps, or submit branch-specific orders.
Immediately after the eight repair updates, compute monitor cross-entropy separately for each branch. If either exceeds capability_limit, request quality is zero. This is a hard constraint on each branch, not an average or a soft penalty. The constraint is checked at the repaired endpoint; it does not assert accuracy or cross-entropy bounds at every later continuation step.
Then fork each repaired state independently for each supplied continuation word. The current words are [0,3], [2,5], and [4,7]. Execute the two listed minibatches and compare the branches' predicted class probabilities on all 12 monitor images. Continuations do not accumulate across words.

Metric
For continuation c, let p_A[c] and p_B[c] be the two 12 by 4 probability arrays. Define D as the mean of (p_A[c]-p_B[c])**2 over all three words, monitor images and classes.
If either repaired branch has cross-entropy above its common capability cap, quality is 0. Otherwise quality is min(1, divergence_limit / D), with quality 1 when D=0. The implementation uses the equivalent numerically safe expression divergence_limit / max(D, divergence_limit). Any legal permutation reaching the threshold earns 1; matching the reference permutation is unnecessary.
Average request qualities within each evaluation capture-sequence group, then average the group means equally. The final score is clipped to [0.0001,1]. Higher is better. The floor applies after aggregation and does not make an infeasible request pass its capability constraint.
The authoritative grade.py executes these equations with float64 learner dynamics and private optimizer moments. It verifies the exact ID set and JSON permutation syntax, assigns zero request quality for a capability violation, aggregates by capture sequence, and clips the final score to [0.0001,1]. Organizer-only answer columns carry compact scoring payloads; they are never public inputs. The public divergence limit includes a one-part-per-million numerical margin for compact float32 private moments.

Intended use and known limitations
This benchmark tests whether a controller can use partial optimizer-response evidence to choose a shared repair order for two hidden Adam states. It is a controlled scientific-ML benchmark, not a method for repairing arbitrary deployed models. The future continuations and monitor labels are fixed and public; the score measures this disclosed workload only.
The 2,100 prepared requests are independently seeded optimizer experiments derived from 192 real photographed frames in 16 capture sequences. There are four evaluation capture sequences. Thus row count should not be interpreted as 2,100 independent source scenes. Construction favors cases with observable order effects, and the hard capability cap can be nonbinding for many feasible orders. A fixed-configuration rank regressor trained on the public training split scored 0.345 on the 420 held-out requests, above canonical order at 0.307 and reverse order at 0.324. This demonstrates modest learned headroom, but does not establish unique recovery of optimizer memories or a strong solution.
