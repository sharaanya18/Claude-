# Learned patterns (grown by /eris-learn from user-supplied challenges and top solutions)

New entries land here first. When a lever is confirmed by ≥ 2 independent challenges, promote it into the right curated file and leave a one-line pointer here.
Entry format: **L<nnn> name** — When (data signal) · What (mechanism, original re-implementation) · Gain (author-reported / measured, unverified?) · Cost/Risk (compute, compliance) · Evidence (slug, rank, confirmations [N×]).
Entries marked DO NOT ADOPT describe ideas whose known implementations fail current platform checks.


**L001 Information ceiling by Monte Carlo (matching / correspondence tasks)** — When: one-to-one matching of items whose cross-view signal is weak and spread over many dimensions (AnchorPerm) · What: measure canonical correlations of true pairs on train, simulate jointly-Gaussian pairs with those correlations, run the ML matcher (Hungarian on the CCA-weighted bilinear score) per hidden-set size, and compare with the model's accuracy; a model within ~5% of that ceiling cannot be improved by capacity, only by new information · Gain: avoided a week of tweaks (clean accuracy 0.56 vs ceiling ~0.57-0.59) · Cost/Risk: assumes a linear-Gaussian generator; nonlinear extras make the true ceiling slightly higher · Evidence: anchorperm, own measurement [1x].

**L002 Simulated-shift proxies can track the platform** — When: the description says held-out representation regimes exist but no train regime label does · What: match unlabeled summary statistics of the evaluation inputs to simulated shifts (letter frequencies -> additive code noise sigma ~0.7; covariance spectrum -> NOT noise, partly changed cross-role map) and report CV per simulated shift next to clean CV · Gain: the simulated-noise and partial-rotation CV (0.585 / 0.572) predicted the platform score (0.58) within 0.01 · Cost/Risk: only a rank-ordering proxy; do not tune to one public number · Evidence: anchorperm [1x].

**L003 Row-local models cannot learn a changed cross-view mapping** — When: train covers one familiar mapping and the evaluation regime changes the role mappings (AnchorPerm transfer rows) · What: tower/bilinear scorers collapse to chance under rotated, sign-flipped or permuted coordinates; rotation/partial-rotation augmentation, QAP structure terms, two-pass pseudo-anchors, Sinkhorn decode, richer heads and context encoders all gave 0 to -0.02 accuracy · Gain: none (negative result worth keeping) · Cost/Risk: the only large lever left is pooling unlabeled/anchor information across evaluation rows, which CLAUDE.md 2.3.5 bans (test-time adaptation) · Evidence: anchorperm, public score 0.5934 / 0.58 vs baseline 0.5616 [1x].

**L004 Platform/sandbox operations** — The platform check (CSV + script) costs a credit: no free probes. Kaggle GPU quota is 30 h per week: spend it on decisive runs, not on dev smoke tests. The cloud sandbox restarts between turns and kills background jobs: keep any run that must finish inside one turn (<= ~10 min foreground calls, or poll in-turn), and checkpoint outputs to the repo. Evidence: grounded_ip_formulation, anchorperm.

**L005 Do not let the score gap drive you toward the compliance boundary** — When: top scores look unreachable with row-local methods (AnchorPerm) · What: the large lift was transductive (pooling test anchors); it was built on a relayed, unwritten "reviewer said yes" and after test summaries had already shaped the augmentation constants; the user rightly pushed back · Gain: none until written approval exists · Cost/Risk: rejection after the competition forfeits the placement; the checker cannot see intent but reviewers read process · Evidence: anchorperm v4 (blocked) [1x]. Rule now in CLAUDE.md 2.3A: written approval saved in reports/reviewer_approval.md or the mechanism stays out; shift families come from the description and train only.

**L006 Estimate the latent state, then simulate** — When: a hidden optimizer/process state determines the metric and the disclosed dynamics are runnable (Shared Adam) · What: learn per-parameter priors for the hidden quantities from public statistics, invert the supplied one-step responses exactly (Gauss-Newton/LM), then score candidate actions by simulating the dynamics under several hypotheses (all five reviewed top solutions did this) · Gain: public 0.589 for a first version of the idea; the top-ranked variants add the levers below · Cost/Risk: needs a batched GPU simulator and exhaustive or near-exhaustive action search; fixed work plan required · Evidence: shared_adam_repair (own run plus five supplied top solutions) [6x].

**L007 Moment buffers are EMAs of gradients along a path** — When: hidden buffers come from a short training history · What: build the correction basis from per-image gradients at the public weights AND at weights moved along a common-step trajectory (or a perturbed point); separate the common part and the A-B difference part, each with its own coefficients and scale · Gain: reported by ranks 1, 3, 5 (not measured by me); my single guessed perturbation gave 0 · Cost/Risk: more basis columns (114-200) per request · Evidence: shared_adam_repair top solutions [3x].

**L008 Learned uncertainty plus in-script decision-rule selection** — When: decisions are made under posterior draws · What: measure block-wise residual spreads on held-out groups, draw states from them, and choose the decision rule (mean log divergence, tail quality, temperature) inside the script on held-out groups with the official metric, keeping canonical/reverse as baselines · Gain: ranks 1, 2, 4 rely on it · Cost/Risk: needs cross-fitted estimators (seeds x folds) · Evidence: shared_adam_repair [3x].

**L009 A public limit can encode the construction effort** — When: the public threshold equals the quality of a reference built by search (divergence_limit = reference order's D) · What: estimate from training data how many random candidates the reference corresponds to (share of random orders within the limit), then use it to turn each hypothesis's divergence distribution into an expected quality · Gain: used by rank 2; I only observed it · Evidence: shared_adam_repair [2x].

**L010 Time and hardware branches still appear in top code** — Rank 4 used a wall-clock alarm, rank 2 a cuda/cpu switch, rank 1 a stated runtime override. Not evidence of acceptance; keep CLAUDE.md section 3 as written.

**L011 Pooled regime adaptation is what the AnchorPerm leaders used (DO NOT ADOPT without written approval)** — When: held-out representation regime, anchors revealed per row · What: all five reviewed top solutions cluster test rows into regimes and fit an anchor-based map or adapter on the pooled revealed anchors (plus self-training on decoded pairs, cross-fitted held-out-anchor safety check) · Gain: it is the large lever my row-local v3 could not reach (0.58 vs baseline 0.5616) · Cost/Risk: test-set use beyond one-row inference, banned by CLAUDE.md 2.3 #5 / 2.3A unless a written reviewer approval is saved; the challenge text allows only "row-local anchor conditioning" · Evidence: anchorperm, five supplied solutions [5x]. Recorded for understanding; not to be built here.

**L012 Compliant AnchorPerm levers** — regime-invariant second-order geometry (item-in-row statistics, Gram matrices, anchor profiles, QAP consistency); row-local dequantisation by quantiser-scale MLE; train-only shift simulation with an anchor-estimated-map regime bank; learned graduated assignment or two-stage pair classifier; seed-ensemble Sinkhorn marginals with Hungarian decode; isotonic confidence on held-out-anchor / out-of-fold rows; stratum-aware validation with the worst-stratum term. Evidence: anchorperm top solutions [3x+].

**L013 When the leaders all break your rule, say so and keep the rule** — The metric rewards the transductive trick, the description is silent, and the whole top-5 uses it. The right responses are: ask for WRITTEN approval, or compete with the compliant levers and accept a lower ceiling. Do not infer approval from the leaderboard. Evidence: anchorperm, own history (L005).

**L014 Learn the task's own target from the full days (self-supervised affinity)** — When: a prefix must be linked to a continuation made of things *not seen in its own prefix*, and many complete sequences are published (Whose Second Half, ~23k full days vs 1,081 labelled rows) · What: build "first-half item -> item that is NEW in the second half" matrices (cosine / lift, rank-weighted by order), kNN votes against new-in-second-half items, or a denoising autoencoder first half -> second half (and back); this is the training signal the task defines, learned from real data, not hand rules · Gain: used by ranks 1, 2, 3 explicitly; not measured by us (our baseline targets all plays and scored 0.54 public) · Cost/Risk: compliant while fitted only on non-test sessions; the learned head must still be trained on labelled rows · Evidence: whose_second_half top-5 [3x explicit, 5x in spirit].

**L015 Refit every learned statistic per fold without the held-out fold's group, and score test the same way** — When: stacking features come from embeddings / counts fitted on the same sessions the labelled rows are built from · What: for fold k drop the fold's prefix sessions (and all test sessions) from IDF, kNN index, co-occurrence, embeddings, autoencoders; generate held-out features from that pool; for test, either use the full pool (ranks 1, 3, 5) or, better, score test under *each* fold pool and average the stacker outputs (ranks 2, 4) so train and test features come from the same regime · Gain: all five do it; the "average over fold pools" variant also removes the corpus-size mismatch · Cost/Risk: 5x the embedding cost (rank 1 trains 48 skip-gram models in parallel) · Evidence: whose_second_half top-5 [5x]. Our baseline mixes 20 feature folds, 5 model folds and `fit_all` kernels: do not trust its OOF.

**L016 Many views of the same sequence beat one tuned embedding** — When: item-to-item affinity is the whole signal · What: train several unsupervised views that differ in what counts as context: wide window over first occurrences, window cut into listening *sittings* by time gaps, local window 2-5, whole-day random pairs, release- and recording-level tokens, PPMI-SVD, LSA; keep **both IN and OUT tables** and score in.out as well as cosine; feed every view as separate channels and let the head weight them · Gain: ranks 1 (8 views, 3 channels each), 3, 4, 5; unmeasured by us · Cost/Risk: gensim `workers=1`, fixed seed, crc32 hashfxn for determinism · Evidence: whose_second_half [5x].

**L017 Token-level interaction head instead of pooled scalars** — When: pooling a prefix to one vector throws away which prefix artist links to the candidate · What: tensor (prefix token x candidate artist x channels); token MLP -> value + attention logit; attention / mean / max pool over tokens with token dropout; pair MLP + group features; sum the candidate's two artists; one context layer with row, column and bundle means · Gain: rank 1 only, the one structurally different idea among the five; unmeasured · Cost/Risk: memory (n x 6 x 96 x 12 x 34 floats), needs per-fold tensors · Evidence: whose_second_half rank 1 [1x].

**L018 Feature-bagged seed ensemble** — When: few labelled rows (1k), many correlated channels · What: each ensemble member gets a fixed random 70 % of channels and 80 % of group features plus its own seed; z-score each member's logits per row and sum; 10 members to choose epochs on one held fold, 20 final · Gain: rank 1 (winner); rank 2 also averages 20 networks; unmeasured · Cost/Risk: fixed member count, no time guard · Evidence: whose_second_half [2x].

**L019 Exact permutation likelihood in the booster and in linear heads** — When: 6x6 assignment, rows small enough to enumerate 720 · What: LightGBM custom objective whose gradient is (exact pair marginal - label) with hessian max(m(1-m), 1e-3), keeping the 36 pair rows of a bundle together; linear heads on log-signed double-centred features trained on the 720-way softmax with snapshot averaging; decode = marginals then Hungarian (or per-prefix argmax when repeats are allowed) · Gain: rank 3 (GBM + RowNet), rank 5 (two linear heads carry 75 % of the blend), rank 4 (searched), none measured by us · Cost/Risk: custom objective needs fixed rounds, deterministic=True · Evidence: whose_second_half [3x]. Related: L001-L013 is the AnchorPerm view of the same decode.

**L020 Double-centre and row-rank everything before the head** — When: only assignment-invariant evidence matters (constants per prefix or per candidate cancel in the joint decode) · What: add x - rowmean - colmean + bundlemean, row/column z-scores and ranks, row-max and column-max normalised copies of every pair score; remove nothing from the raw scale · Gain: used by 2, 3, 4, 5 [4x]; cheap · Evidence: whose_second_half.

**L021 Listener-fingerprint features separate same-taste people** — When: rows are built so taste is nearly identical (here: "grouped because first halves are similar") · What: habits independent of genre: share of plays with empty release, recording rarity / "hit level" vs artist level, repetition and run length, median inter-play gap, album-run share, whether an artist was played in the last sitting, how many *other prefixes of the same row* share an artist (exclusive-bag signal), match of the continuation's first-play metadata to those habits (binomial log-likelihood of empty-release count under the prefix's rate) · Gain: ranks 2, 3, 4 include it, rank 4 ablates style vs taste in-script; unmeasured by us · Cost/Risk: derived only from the row's own prefixes and candidates, so compliant · Evidence: whose_second_half [3x].

**L022 In-script selection grids for blend weight, temperature and decoder** — When: several scorers and a decode with free scalars · What: after OOF scores exist, search a tiny fixed grid (blend weight {0..2}, temperature {0.25..3}, decoder in {Hungarian, per-prefix argmax of marginals}) on OOF accuracy; rank 4 additionally uses 24 seeded TPE trials for the head and selects the decoder only on the HPO folds, then reports the folds HPO never saw · Gain: small, mostly insurance · Evidence: whose_second_half ranks 2, 3, 4 [3x]. Copy rank 4's honest-reporting block (per-fold mean/std/min, unseen-fold mean, single-seed spread, tercile slices, train-probe gap).

**L023 Supervised column selection and test-candidate sentences are risky (DO NOT COPY)** — Rank 5 selects ~384 of ~650 columns per family by effect size on *all* OOF labels before any validation, sorts train rows by id before folding, and appends every continuation (including test rows' candidates) to the word2vec corpus. Selection leak and test-candidate use are exactly what 2.3 #5 and the reviewers look for. If selection is wanted, do it inside each fold, and keep the embedding corpus to non-test full days. Evidence: whose_second_half rank 5.

**L025 Whose Second Half: what each of the five ranked solutions did (read from code, scores not supplied, nothing re-run)** —
Rank 1: 8 skip-gram views refit per fold (6 artist views: first-occurrence order, sitting-cut at 600/1800/7200 s, local window 5, sparse/dense; plus release and recording level), IN and OUT tables, 7 count matrices incl. first-half -> new-second-half; token-level head over (prefix artist x candidate artist x ~34 channels) with attention/mean/max pooling and a row/column/bundle context layer, row+column CE, 20 feature-bagged members (70 % channels, 80 % group features), z-scored logits summed, Hungarian; test from the full non-test pool.
Rank 2: all corpus refit per fold; denoising autoencoder h1<->h2, shifted-PPMI SVD (192d), idf session-kNN, windowed session-kNN (25/50-play windows, artist/release/recording, query expansion), listener-profile features double-centred in the bundle; LightGBM (3 seeds) + equivariant bundle net (20 seeds), blend weight and temperature picked on OOF, marginals then Hungarian; test scored under each fold corpus and averaged; ~49 min of 90.
Rank 3: item2vec x4 + PPMI-SVD + LSA + item-item cooc + kNN votes (all and new-in-second-half) + IN.OUT affinities + release/empty-release habit; LightGBM with the exact 720-permutation custom objective + RowNet (attention over prefix artists with 11 per-artist inputs incl. how many other prefixes of the row share the artist, recency in plays and seconds, last-sitting flag), exact permutation NLL; blend weight and temperature on OOF; argmax of exact marginals; test from the full pool.
Rank 4: hand-written torch skip-gram (wide 10, near 2, day-level random pairs; 3 seeds), PPMI-SVD, co-listening, decayed transitions, listening-style features (repetition, run length, album share, gaps, track popularity); equivariant set matcher, Optuna 24 seeded TPE trials, 5 seeds, decoder (per-prefix argmax vs Hungarian) chosen on HPO folds; test under each fold space, marginals averaged; full diagnostics (per-fold, unseen folds, single-seed spread, strata, train-probe gap, style ablation).
Rank 5: five fold-refit families (count affinities with kNN and entity affinities, PPMI-SVD variants, CBOW/skip-gram, all-graph SVD), ~650 columns each selected by supervised effect size, 2 CatBoost + separate structured CatBoost + 2 linear heads on the exact 720 likelihood (weights .25/.375/.375), temp .5, Hungarian; flags in L023.
Common core and what probably separated ranks (hypothesis): resolution of evidence (rank 1's token tensor), number of views x members (ranks 1, 2), matching train/test feature regime (ranks 2, 4), row context in the head (ranks 1-4). Evidence: whose_second_half [5x]. Compliance read: ranks 1-4 clean by our standard (rank 2 uses non-warn deterministic algorithms, rank 1 forked pools: keep determinism checks); rank 5 see L023.
