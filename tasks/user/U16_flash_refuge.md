# U16 — Flash Refuge (user-supplied, verbatim; compute: one GPU 24 GB, 1 hour total)

## Overview
A lighting choice that helps one part of a scene can leave another in shadow or make it too bright. A single promising capture also becomes useless if that capture is lost. Predict the complete set of smallest reliable inspection portfolios for several requested regions of a real scene.
You receive three registered scout photographs and lighting calibration observations. Eight different candidate lighting commands are available for subsequent captures. Their calibration observations are supplied, but their scene photographs are withheld at test time. Each query specifies acceptable brightness gains for several rectangles and a capture budget. Predict every inclusion-minimal portfolio that would satisfy every region even if any one selected candidate capture were lost. A case can have several equally valid portfolios of different sizes, or none. The imagery is captured data; the region requests are constructed queries over those measurements. Adequacy means satisfying the stated brightness interval.

## Files and columns (paths relative to the prepared public data directory)
train.csv (training queries and portfolio targets); test.csv (test queries, same feature columns); sample_submission.csv (valid-format baseline with the two submission columns); settings.json (tensor dimensions, candidate count, brightness weights, offset, required redundancy); train/<scene_id>.npz and test/<scene_id>.npz (input tensors); train_measurements/<scene_id>.npz (supervised response maps for training scenes only; no test scene).
train.csv columns: id (query key), scene_id, group_id (anonymous physical-room group; use for validation), scene_path, query (JSON: region rectangles, acceptable gain bounds, capture budget), portfolios (JSON training target; absent from test.csv). Identifiers anonymous; numeric/byte patterns have no intended predictive meaning.
Input NPZ contains exactly scouts (3,160,240,3), scout_calibration (3,32,32,3), candidate_calibration (8,32,32,3), all uint8 RGB channels last. Scout calibration index v corresponds to scout image v. Candidate calibration index k identifies local command k for that scene; local indices have no shared command identity across scenes. The sphere observations describe incoming illumination and may be used as model inputs. Spatial reflections are applied consistently to images, response labels, query coordinates and calibration observations.
A training measurement NPZ contains exactly candidate_luminance: finite float32 (8,160,240); index k corresponds to candidate k in that training scene. These are labels derived from actual candidate photographs. You may train on these maps, derive supervised patch gains, or use the portfolio targets directly. No equivalent file exists for a test scene. You must not substitute a training scene's map for a test scene's prediction.
settings.json contains candidate_count, scout_count, height, width, calibration_height, calibration_width, gain_offset, luminance_weights, adequate_captures_required.

## Query semantics
query: integer budget in {4,5,6} and regions (3 to 6 entries) each [x0,y0,x1,y1,lower_gain,upper_gain]; first four integers are the half-open rectangle [x0:x1, y0:y1] in an image 240 wide and 160 high (NumPy image[y0:y1, x0:x1]); last two positive reals with lower_gain < upper_gain.
Brightness of an RGB pixel = (0.2126 R + 0.7152 G + 0.0722 B)/255 (proxy in the recorded display image). For candidate k and region j take the median candidate brightness in the rectangle and divide its offset value by the offset median brightness of scout 0: gain[k,j] = (median_candidate[k,j] + 0.02)/(median_scout_0[j] + 0.02); adequate[k,j] = lower_gain[j] <= gain[k,j] <= upper_gain[j] (inclusive). Compute luminance before taking its median (not per-channel medians). Same denominator scout for every candidate. Each candidate is photographed separately; do not add candidate maps together.
A portfolio P is successful when it has at most budget candidates and, for every region j, sum(adequate[k,j] for k in P) >= 2 (every region remains adequately recorded after loss of any one selected capture). Past scout captures are not eligible. A successful portfolio is inclusion-minimal when removing any selected command makes it unsuccessful. Return ALL inclusion-minimal successful plans (not one preferred plan, not all supersets); if none fits the budget, return [].

## Submission and metric
CSV exactly id,portfolios; preserve every test id. portfolios is a JSON array of integer bit masks; bit k selects candidate k (0..7); e.g. 14 = candidates 1,2,3; empty family is [] (empty CSV field not allowed). Each mask selects two through six commands; booleans, floats, strings inside the array, repeated masks, missing values, malformed JSON rejected. At most 70 masks; must be an antichain (no listed mask strict subset of another). Incorrect plans, including plans exceeding the query's budget, are false positives.
Per-case score: 1 when both true and predicted families are empty; else 2*|T ∩ P|/(|T|+|P|); empty-vs-nonempty scores 0. Final = max(0.01, mean case score), capped at 1. Exact masks only. Flooding the family with alternatives decreases precision. Duplicate ids and missing test ids rejected; the evaluator may score only one shard while receiving the full test submission (ids outside the shard ignored for scoring but syntax checked); reserved visibility column ignored if present; other extra columns rejected.

## Validation, resources, permitted information
Use group_id to keep an entire physical room together in validation (repeated queries and different views of the same room otherwise make validation optimistic). Training rooms, public evaluation rooms and private evaluation rooms are disjoint. Solve budget one hour including setup, training, and complete test inference on a single GPU with 24 GB VRAM. General pretrained visual weights permitted. Train your task-specific predictor using the released training data. Any architecture and any correct method for enumerating portfolios from learned response estimates; a dense relighting model is not required. Use the released images, calibration observations, requests and training labels as the task evidence. Do not identify or retrieve the original capture archive, recover test photographs from outside repositories, fingerprint public imagery against external material, look up source identifiers, or use creator construction artifacts, archive ordering, filenames or file sizes as label channels. Your output should describe its validation and runtime evidence clearly.
