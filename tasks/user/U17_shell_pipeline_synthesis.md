# U17 — Unseen-pair shell pipeline synthesis (user-supplied, verbatim; CPU, from scratch)

## Task
Systematic compositional generalization in program synthesis. Programs are shell pipelines: one to three stages, each led by a command head and connected by pipes. The split is built on composition structure rather than text. Seven ordered head-to-head adjacencies (which command feeds which) are withheld from training entirely, and every evaluation program contains at least one. Every head involved is demonstrated in at least twenty training programs, so each part has been seen; only the way the parts connect is new.
Given an English specification, write the complete program: flags, literal arguments, quoting and the data flow from one stage into the next. Outputs are open strings. Because no training program contains a withheld adjacency, no memorized training program can be copied to an exact answer, and nearest-neighbour retrieval is limited to partial credit. A solver must learn what each stage contributes and assemble a new connection it has never observed. The benchmark isolates whether a model can recombine known program components under a held-out composition rule.

## Dataset
train.csv (4,107 labeled original cases: id,input,output), test.csv (160 unlabeled cases: id,input), sample_submission.csv (deterministically selects format examples from training outputs without consulting test answers; not a fitted baseline). id is an opaque alignment key and not a predictive input. No command-group identifiers released. input is an English description of a command-line operation; literal names or patterns in the description are part of the requested program.
Preparation restricts commands to one to three outer pipeline stages; pipes inside quotes are not separators; commands containing semicolons, command substitutions, backticks, logical AND/OR, or selected execution wrappers are excluded. A command head is the first shell word of an outer stage.
Seven ordered command-head pairs are assigned to evaluation. Every training command containing any held-out pair is excluded, including longer pipelines with that pair as a subpath. Every evaluation command contains at least one held-out pair. Evaluation covers six of the seven excluded ordered pairs with at most 50 cases per represented pair; the seventh remains excluded from training but contributes no evaluation cases. Each evaluated head has at least twenty original training examples. Canonically tokenized complete commands form groups; identical requests with conflicting references are removed. Groups and exact commands do not cross splits. Held-out pair list and split labels are not inputs. Training requests sharing any contiguous five-word span with an evaluation request are excluded; shorter components and argument patterns can recur. Evaluation references have distinct canonical commands. Reference curation includes Bash parse-only validation, conservative find-expression checks, removal of identified request/reference contradictions. Descriptions can omit platform context; alternatives not exhaustively annotated. Strings are never executed.

## Submission format
Exactly id,output, one row per test ID, no extra IDs; one nonempty command string of at most 4,096 characters with balanced POSIX-style quoting; preserve literal backslashes, quotes, punctuation using CSV escaping. Example row: example_case,finger $username | awk '/^Directory/ {print $2}'. Missing, extra, reordered or duplicate columns; malformed CSV; missing/extra/duplicate/blank/padded IDs; non-string, empty or over-length outputs reject the entire submission. Null bytes forbidden. The grader uses POSIX shlex tokenization to reject unbalanced quoting (lexical check only).

## Evaluation
Tokenize Unicode word runs and each non-whitespace punctuation character after the quoting check. P, T = predicted and recorded token sequences. Levenshtein distance D (unit costs). Sequence similarity = 1 - D/max(len(P), len(T), 1). Case score = 0.5*similarity + 0.5*exact (exact = 1 only if complete sequences match). Final = arithmetic mean over cases; 0..1; token multiplicity and order matter. Compares with the recorded reference, not semantic equivalents; does not establish execution correctness.

## Expected approach and rules
Learn the roles of demonstrated command heads, retrieve or generate compatible command fragments, compose them with argument copying and correct quoting. A whole-command retrieval model is a partial-credit control with zero exact-match capability on this split; generation or fragment composition is necessary for exact answers. For local validation, group public training rows by canonically tokenized output so paraphrases of the same command do not cross your local split. This existing challenge uses CPU computation for training, feature extraction and inference. Train learned components from scratch using the supplied public files.
What not to use: pretrained models, embeddings, weights or external labeled corpora; original-source lookup, recovered source identifiers, hidden outputs or hardcoded test answers; case IDs as predictive features.
