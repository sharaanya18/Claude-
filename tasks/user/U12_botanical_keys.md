# U12 — Walking botanical identification keys from species descriptions (user-supplied, verbatim minus site chrome; Domain NLP, Medium, A10G)

## Overview
Each test row gives a written botanical description of one plant or moss taxon, with its name removed, and the id of an identification key. For every couplet of that key, decide which lead the described taxon would follow. Those decisions define your walk through the key, from couplet 1 down to a taxon. Each decision on the correct walk is scored on its own.
An identification key is a decision tree written in natural language. Each couplet offers two (rarely three) contrasting leads such as "Costa failing below apex" versus "Costa percurrent to excurrent". A lead either sends you to another couplet or ends at a taxon. Keys are terse and comparative, lean on measurements, ranges, negations ("plants not combining the above features") and habitat or range notes. The species descriptions are written independently, in a different order and level of detail.
Keys and descriptions come from one regional flora in south-eastern Australia: flowering plants, conifers, ferns and mosses. The test keys never appear in training, and neither do their taxa. You have to learn to read couplets against descriptions in general.

## Dataset
key_leads.csv: one row per lead, covering every key used in train or test. The key is a tree: couplet 1 is the root; each couplet has 2 (in three couplets, 3) leads. Couplets are numbered depth-first. Columns: key_id; lead (couplet number followed by a letter, e.g. 3b); text (the lead statement; names of the taxa the key separates are replaced by [taxon]); goes_to (either a couplet number of the same key, or, when the lead ends the walk, an opaque taxon label T01, T02, ... unique within the key; numbering carries no meaning).
train.csv and test.csv: one row per (key, taxon) pair; test.csv has the same columns except path. Columns: id; key_id; description (morphological description; own name replaced by [taxon]); habitat (may be empty); distribution (range notes; may be empty); phenology (may be empty); path (train only: correct walk as space-separated lead labels from couplet 1 to the taxon, e.g. 1b 2b 3a).
Counts: 4,989 train rows over 970 keys; 482 test rows over 56 keys. Train walks pass through 1-27 couplets (median 3). Every test walk passes through at least 4 couplets (median 6, max 30). Test keys have 4-144 couplets; half of the test rows belong to keys with at least 22 couplets. 12,865 leads in total.
Worked example (train): key key_a60806413c leads: 1a "Plants to 5 mm tall; laminal cells smooth" -> T05; 1b "Plants usually taller than 5 mm; laminal cells papillose or prorate" -> 2; 2a "Laminal cells with a large central papilla; plants white to glaucous green" -> T04; 2b "Laminal cells prorate; plants usually yellow-green" -> 3; 3a "Costa failing below apex" -> T02; 3b "Costa percurrent to excurrent" -> 4; 4a "Most leaves 0.7-1.5 mm long; leaf margin recurved; apex acute to acuminate" -> T03; 4b "Most leaves 1.5-2.3 mm long; leaf margin plane; apex acute" -> T01. Row description starts "Loose tufts on soil. Stems c. 25 mm long. Leaves wide-spreading ... costae failing below apex; ... laminal cells rectangular ... prorate. Sporophyte unknown." Stems of 25 mm rule out 1a so 1b; prorate cells -> 2b; costa failing below apex -> 3a (ends at taxon). Correct walk 1b 2b 3a; couplet 4 not on this taxon's walk, any decision there ignored. A full set of decisions could be 1b 2b 3a 4b.
Descriptions do not always mention the character a couplet asks about (in the example no plant colour so 2b chosen on cells alone). Some leads can only be decided from habitat or distribution, or by eliminating the other lead. A few descriptions cover a subspecies or hybrid briefly or by comparison with a relative. Keys and descriptions were written separately and occasionally disagree on a character. The correct walk is always the one the key itself uses to reach the taxon.

## Submission
CSV columns id, decisions: space-separated lead labels, at most one per couplet of the row's key, in any order, e.g. 1b 2a 3a 4b 5a. Give a decision for every couplet of the key; the scored couplets are the ones on the correct walks, which you do not know. A couplet with no decision counts as wrong. Commas also accepted. sample_submission.csv picks lead a everywhere.

## Evaluation
Only couplets on the correct walks of test rows are scored. For couplet c in one key: R_c = test rows whose correct walk passes through c; m_c = number of different leads those walks take there. If m_c = 1, not scored. Otherwise for each lead b taken by some row in R_c, recall_b = share of rows whose correct walk takes b and whose decision at c is b. J_c = (mean_b recall_b - 1/m_c) / (1 - 1/m_c). Final = sum_c |R_c| J_c / sum_c |R_c|, clipped to [0,1]. J_c = 1 when every row's decision at c is correct; 0 for any rule giving every row the same decision at c (always a, or the lead above more taxa); can be below 0. Each decision is scored on its own (a wrong decision at couplet 2 does not stop couplet 5 counting). A decisions cell with anything other than lead labels or answering the same couplet twice gives no decisions (all its scored decisions wrong). Whole submission rejected if columns not exactly id,decisions, any test id missing/duplicated/unknown, or row count differs.

## What not to use
Real machine learning is required: train or fine-tune a model; purely rule-based or algorithmic solutions not accepted however well they score. All training happens inside your solution script. General-purpose pretrained backbone weights allowed (BERT-style encoder or small language model openly downloadable, not task-specific); not weights fine-tuned elsewhere (e.g. on this data); hosted model APIs not allowed; neither is choosing test decisions with a pretrained model not trained on the provided data (zero-shot/few-shot prompting). No external data of any kind (other floras, keys, trait databases, herbarium records, copies of this data, web look-ups). No synthetic data (do not generate extra training data with another model or otherwise and train on it). Test data is for one-row (or one-batch) inference only. Predict each test row on its own. No pseudo-labelling, test-time adaptation, reweighting training samples using the test set, calibrating/balancing outputs using the distribution of test predictions; that includes coordinating decisions across test rows that share a couplet or a key. No manual work on test rows; no hard-coded answers or test-id dictionaries. TF-IDF, n-gram, Markov-chain and similar frequency-based methods are allowed or disallowed at the reviewer's discretion.
Compute: A10G.
